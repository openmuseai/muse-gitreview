# Repository Review 0.1.0 产品定义

## 目标与边界

独立、通用的代码审阅插件，安装在 Desktop/Mobile 应用中。Muse-CI、DSH 和其他插件均可提供变更来源并调用它。优先消费 Host 既有版本快照、Diff 和授权能力；不维护第二个版本库，不把 CI 状态机或 Git 平台凭据加入 Host。

先按实际公开能力发现来源，再显示可用操作。来源模型覆盖文件保存版本、仓库工作区/暂存区、分支、提交、MR。Host 内部已有实现但未提供插件合同的操作显示为待接入；不能用示例数据假装实际仓库能力。

## 审阅信息架构

Desktop：顶部显示仓库、来源模式、基线与目标引用；左栏显示文件树、搜索及变更统计；主体为文件 Diff；右侧意见区按需打开。Mobile：保留来源与固定 SHA，文件列表使用抽屉，默认统一 Diff；行号窄列、代码横向滚动，可切换自动折行。外屏不压缩并排视图的字体。

每次比较固定来源与内容摘要；切换引用生成新比较，不把旧“已阅”或意见自动搬到新 SHA。MR 页面明确区分草稿/提审、平台 Review 与合并状态。

## Diff 交付标准

- 保持原代码语法高亮；TS/JS、JSON、Python、Dart、Rust、Shell、HTML/CSS 等按语言解析，未知语言安全回退纯文本。
- 增删底色与语法前景分开；同时保留 +/- 与新旧行号，不能仅靠颜色表达变化。
- Desktop 支持统一/并排，左右行对齐；修改行提供行内增加/删除高亮。
- 默认折叠未修改上下文，可逐段展开；文件标题保留路径、重命名前路径和 +/- 统计。
- 文件树显示新增、删除、修改、重命名、二进制；可搜索路径、切换文件、标记“已阅”。“已阅”只表示阅读，不等于批准或合并。
- 二进制、缺失补丁、被截断和来源过期必须独立提示，不显示假空白比较。
- 处理不可信路径和源码时只按文本渲染；不执行源码、链接、HTML 或仓库命令。

## 合同与能力复用

消费 Host/已安装 Provider 的公开发现与授权；用固定引用和结果快照驱动视图。插件发布自己的审阅合同（打开比较、读取比较、记录意见与导出结果），不要求调用方依赖 Muse-CI。来源适配与渲染分离。CI 复用已有 ci_mr_diff 和平台回执，传递可审阅变更；不新增一套 CI 专属 Git 凭据。

具体 Host/MCP 合同及缺口见 HOST-CAPABILITIES.zh-CN.md。首版先完成这一盘点，再实现已有能力适配；不假设一个尚未发现的 Host tool 名称。

## 验收

CAP-01 运行时能力发现；CAP-02 版本引用不可替换；CAP-03 权限/离线/过期可恢复；CAP-04 非 CI 调用方能使用相同合同。

UI-01 实际代码有语法高亮；UI-02 统一与并排增删修改行数正确；UI-03 行内修改保持语法颜色；UI-04 搜索与文件切换；UI-05 上下文展开；UI-06 二进制、重命名、缺失/截断；UI-07 长行、Unicode、空文件、无结尾换行、恶意 HTML 安全。

MR-01 指定真实仓库与 MR；MR-02 固定 head SHA/过期检查；MR-03 分页完整性；MR-04 已阅/意见绑定具体比较；MR-05 不将查看/本地验收当平台批准。

E2E-01 Desktop 安装并实际打开；E2E-02 Find N6 普通 App 应用 Tab；E2E-03 国内公网中转；E2E-04 展开/外屏实测高亮与增删改、切换文件、审阅记录；E2E-05 Muse-CI 中保存版本与需求材料、真实测试和 MR 回执。


方案选型：按 ADR-001 分别复用 Host 的文件版本权威、DSH 同源 jsdiff 与 Shiki 路线，统一到独立审阅插件。原生 Host 当前 _lineDiff 不作为公共引擎；Git/MR 作为独立来源保留原始行号与固定提交。当前完成选型与 CI 首版定义，未完成插件构建/安装/真机验收。
